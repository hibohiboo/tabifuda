## ハマりどころ

- **python コマンド**: このマシンでは `python3` が Windows Apps の
  スタブを指し動かないことがある。`python`(実体は Python 3.14、
  `/c/Python314/python`)を使う
- **一時的な検証データの復元**: 「意図的に壊してビルド失敗を確認 →
  `git checkout <file>` で戻す」という検証手順は、そのファイルに
  他の未ステージの変更が乗っていると一緒に消える。復元前に
  `git status` でそのファイルが他に変更を持っていないか確認する
- **cargo clippy はデフォルトで `#[cfg(test)]` コードを検査しない**:
  `cargo clippy --workspace -- -D warnings`(ci.yml と同じ)は `--tests`
  無指定のため、テストコード内の警告(例: non_snake_case、unused_imports)
  を検出しない。`cargo test --workspace` は検査するため、テスト関連の
  警告に気づくのは test 実行時になる(fork.rs の未使用 import 警告が
  pre-existing で残っている。C3のスコープではないので触らない)
- **mermaid 本体は重い**: 素で import すると初期バンドルが約871KB
  (gzip 239KB)まで膨らむ。動的import(`import("mermaid")`)で
  RDRAビュー表示時のみ読み込む形に既にしてある(tools/docs-site/src/Mermaid.tsx)。
  C3 で新たに重い依存(zodなど)を足す場合、それ自体は軽量なので恐らく
  問題ないが、バンドルサイズは `pnpm build` の出力で都度確認する
