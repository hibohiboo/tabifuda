# マイグレーション規律と守備範囲
## マイグレーション規律

- 適用済のマイグレーションファイルは編集しない。修正は新しいマイグレーションで行う
- 本番・ステージングはロールバックせず、前進のみ(forward only)で修正する。開発DBだけはリセットしてよい
- UNIQUE / NOT NULL などの制約を既存テーブルへ追加する前に、違反する行がないか読み取り専用の検査クエリで確認する
- 値が変わる業務設定（税率・料金表）は関数にハードコードせず、設定テーブルを参照する（変更のたびのデプロイをなくす）

## DBが守るもの/アプリが守るもの

DB(制約で守る)|アプリ（コードで守る）
--|--
一意性（UNIQUE）|認可（誰がどの行を見られるか）
参照整合（FK）・値域（CHECK）|業務フロー(ステータス遷移の順序)
同時実行で破れる不変条件|外部サービスとの整合

判断基準： 「 UIを通らない書き込み（バッチ・手動SQL・バグ）でも絶対に壊れてはいけないか？ 」 -> YesならＤＢ制約、Ｎｏならアプリに書く
