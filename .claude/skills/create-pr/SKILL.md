# create-pr （ＰＲ本文を構造化して投稿する）

## 1. 差分と経緯を集める
- `git diff main...HEAD` で変更の全体を把握する
- 対応するプラン (.claude/plans/) と実装後のＡＩレビュー結果を読む

## 2. 本文を下書きする

次の見出しで、レビューアーが上から読めば理解できる順に書く

- 課題: 何を解決するPRか（背景と、対応するissue・プラン）
- 解決策： どう変えたか。設計判断とトレードオフを１～２行で
- テスト: 追加・変更したテストと、手元での実行結果
- レビュー観点: とくに見てほしい箇所、影響範囲、未対応事項

下書きは docs/pr/ に保存し、投稿前に人間の承認を得る

## ３． 投稿する
承認後、`gh pr create` で本文を渡脚て作成する。 CIとAI相互レビューが回るので、その結果が出てから人間のレビューへ回す
